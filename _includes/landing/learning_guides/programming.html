1. Antes de aprender nada, es necesario entender el "mapa"

Muchas personas creen que aprender programación solo sirve para convertirse en desarrollador, pero en realidad la programación es solo una herramienta y se utiliza en muchísimas áreas diferentes. Antes de decidir qué aprender, conviene conocer las principales posibilidades.

Desarrollo de software

Es la salida profesional más conocida. Consiste en crear aplicaciones, sitios web, videojuegos, aplicaciones móviles, APIs y todo tipo de software.

Es ideal para quienes disfrutan resolver problemas y construir cosas. Muchas veces se trabaja en equipos formados por varios desarrolladores y también personas que cumplen otros roles dentro del ciclo de vida del software.

Ciencia de datos

Consiste en obtener información útil a partir de grandes cantidades de datos.

Se utiliza en negocios, salud, deportes, investigación y prácticamente cualquier industria.

Inteligencia Artificial y Machine Learning

Se dedica a construir sistemas capaces de reconocer patrones, hacer predicciones o generar contenido.

Es un área que combina programación, matemática y análisis de datos. El cálculo y la estadística son dos áreas de la matemática que importan mucho en este sector.

Ciberseguridad

Se enfoca en proteger sistemas, redes y datos frente a ataques.

Quienes disfrutan investigar cómo funcionan las cosas suelen sentirse muy cómodos en este campo.

Cloud e infraestructura

Hace posible que las aplicaciones funcionen de manera confiable en servidores y centros de datos distribuidos por todo el mundo.

Quality Assurance

Los expertos en esta área se dedican a probar el software y asegurarse de que cumpla con parámetros de calidad y con las especificaciones.

Hoy, la mayoría de esas pruebas se hacen de forma automatizada y para eso se usan lenguajes de programación y frameworks que permiten interactuar con el software para ejecutar las pruebas y determinar si fueron exitosas o no.

Bases de datos

Casi toda aplicación necesita almacenar información y las bases de datos suelen ser uno de los componentes preferidos para eso.

Existen especialistas cuyo trabajo consiste en diseñar, optimizar y mantener esos sistemas.

Arquitectura de software

Cuando los proyectos crecen, alguien debe decidir cómo organizar cientos o miles de componentes para que el sistema siga siendo mantenible durante años. Ese es el trabajo de un arquitecto de software. El arquitecto, muchas veces, es un programador experimentado.

Sistemas embebidos, robótica e Internet de las Cosas

Programar dispositivos físicos, sensores, electrodomésticos, automóviles, drones o robots.

Videojuegos

En la industria de los videojuegos no solo existen programadores (cuyo trabajo es muy similar al de cualquier otro programador en otras industrias). También hay especialistas en motores gráficos, física, inteligencia artificial, networking y herramientas para desarrollo de juegos.

Investigación

Muchas universidades y empresas desarrollan nuevas tecnologías, nuevos algoritmos y nuevos modelos de inteligencia artificial.

Lo importante

No es necesario decidir hoy mismo cuál será tu especialidad. De hecho, la mayoría de las personas cambia varias veces de área durante su carrera.

El objetivo inicial es descubrir qué posibilidades existen, no elegir para siempre.

2. ¿Cómo está organizado todo este mundo?

Una de las mayores fuentes de confusión para quienes empiezan es que escuchan hablar de cientos de nombres diferentes y creen que todos representan lo mismo cuando en realidad pertenecen a categorías distintas. Comprender esto elimina gran parte de la sensación de caos.

Lenguajes de programación

Son la forma en que escribimos instrucciones para la computadora. Ejemplos:

  • Python
  • Java
  • C#
  • JavaScript
  • Go
  • C++

No es necesario aprender muchos. Aprender uno bien hace que aprender el siguiente sea muchísimo más fácil. Aunque no necesariamente hay que quedarse con un único lenguaje.

El punto medio que muchas veces se recomienda es el de dominar al menos un lenguaje de "scripting" (Python, JavaScript, Ruby, Bash, etc.) y uno compilado (Java, Rust, Go, C++, etc.), porque cada tipo de lenguaje te enseña a pensar de formas distintas y resuelve problemas en contextos diferentes. Sin embargo, también depende de tu especialidad. Si solo haces front-end web, quizás no necesites C. Si solo haces ciencia de datos, quizás no necesites Rust. Si solo haces DevOps, Bash y Python pueden bastarte.

Frameworks

Un framework es una base ya preparada para desarrollar cierto tipo de aplicaciones. No reemplaza al lenguaje sino que está construido sobre él. Incluso, algunos frameworks ofrecen variantes para más de un lenguaje.

Es simplemente código ya escrito por alguien (o por varias personas) para ahorrarte parte del trabajo y poder avanzar más rápido. Por ejemplo:

  • Python: Django, FastAPI, Flask
  • JavaScript: React, Angular, Vue
  • C#: ASP.NET Core
  • Java: Spring Boot

Bibliotecas (librerías)

Son conjuntos de herramientas que resuelven problemas específicos. Por ejemplo:

  • procesar imágenes
  • conectarse a una base de datos
  • crear gráficos
  • trabajar con inteligencia artificial

Normalmente usarás muchísimas durante tu carrera.

Compiladores e intérpretes

Son programas que permiten ejecutar el código que escribas. Cada lenguaje utiliza mecanismos diferentes.

Como principiante no necesitarás preocuparte demasiado por esto, pero es importante saber que, en algún punto del proceso, intervienen herramientas de este tipo.

IDEs y editores

Son las herramientas donde escribimos el código. Visual Studio Code, Visual Studio, IntelliJ IDEA o PyCharm son ejemplos.

Muchas veces ofrecen herramientas adicionales, como autocompletado de texto, resaltado con colores, detección de errores de sintaxis, etc.

Depurador o Debugger

Se usa para encontrar, aislar y corregir problemas ("bugs") en un programa.

Permite controlar la ejecución del código en tiempo real para ver qué falla y por qué.

Bases de datos

Son sistemas especializados para almacenar información. Las hay de muchos tipos.

Un lenguaje muy popular, utilizado en cierto tipo de bases de datos, es SQL.

Git

Git merece una categoría aparte. Porque no sirve para programar sino para registrar cambios en el código y trabajar en equipo. Incluso trabajando solo es una buena práctica utilizar Git, porque ayuda a ordenar las modificaciones y cómo va avanzando el proceso de desarrollo.

Es una herramienta prácticamente obligatoria para cualquier desarrollador profesional.

Todo esto forma un ecosistema

Un proyecto real suele combinar muchas piezas.

Por ejemplo:

  • un lenguaje
  • uno o varios frameworks
  • varias bibliotecas
  • una base de datos
  • Git
  • un editor
  • herramientas de despliegue ("deploy")

Eso no significa que tengas que aprenderlas todas desde el principio. Simplemente cumplen funciones distintas.

3. ¿Qué deberías aprender primero?

Acá creo que está uno de los errores más comunes, porque muchas veces podemos dedicar demasiado tiempo a buscar "el mejor framework" cuando todavía no aprendimos a programar (es parecido a querer elegir el mejor modelo de auto antes de aprender a conducir). Pero el orden importa mucho más que la herramienta.

Mi recomendación sería algo así:

  • Elegí un lenguaje adecuado para tu objetivo.
  • Aprendé los conceptos básicos mientras escribís código.
  • Empezá proyectos pequeños cuanto antes.
  • Usá IA para destrabarte, pero no para pensar por vos.
  • Incorporá Git desde tus primeros proyectos.
  • Cuando los proyectos empiecen a quedar chicos, aprendé el framework correspondiente.
  • A medida que aparezcan nuevas necesidades, agregá las herramientas que realmente vayas a usar.

¿Qué lenguaje elegir para empezar?

Elegir el primer lenguaje no es una decisión para toda la vida, pero sí conviene evitar opciones demasiado antiguas o con comunidades muy pequeñas, porque vas a encontrar menos material para aprender, menos ejemplos y menos oportunidades laborales.

Si bien los conceptos importantes existen en todos los lenguajes, eso no significa que todos sean igual de convenientes para empezar. Cambiar de un lenguaje moderno a otro suele ser relativamente sencillo; pero empezar con uno que casi no se usa hoy puede hacer tu aprendizaje más difícil y limitar las oportunidades para practicar o conseguir ayuda.

Una buena elección suele ser un lenguaje que cumpla tres condiciones:

  • Tiene una comunidad grande y activa.
  • Se utiliza profesionalmente.
  • Cuenta con abundantes recursos, documentación y proyectos de ejemplo.

Además, si ya sabés qué área te interesa, podés elegir un lenguaje que sea especialmente común en ese campo:

Si te interesa... Un buen punto de partida puede ser...
Desarrollo web backend Python, C# o Java
Desarrollo web frontend JavaScript (y más adelante TypeScript)
Desarrollo móvil Android Kotlin
Desarrollo móvil iOS Swift
Ciencia de datos e IA Python
Videojuegos C# (Unity) o C++ (Unreal Engine)
Sistemas embebidos C o C++

Si todavía no tenés claro qué querés hacer, Python suele ser una de las opciones más recomendables para empezar porque tiene una sintaxis sencilla, una comunidad enorme y se utiliza en muchas áreas distintas. C# y Java también son excelentes alternativas si tu objetivo principal es trabajar desarrollando software.

Ahora tu objetivo no debería ser encontrar el lenguaje perfecto, sino empezar con uno que tenga futuro, aprender bien los conceptos y ganar experiencia construyendo proyectos. Después cambiar de lenguaje será mucho más fácil.

¿Cuándo aprender frameworks?

Una buena regla práctica es esta: No estudies un framework porque alguien dijo que está de moda. Estudialo cuando empieces a construir un tipo de aplicación para el que ese framework fue diseñado.

Por ejemplo:

  • Si vas a desarrollar APIs con Python, probablemente tenga sentido aprender FastAPI o Django.
  • Si vas a crear aplicaciones web con C#, aprenderás ASP.NET Core.
  • Si vas a desarrollar interfaces web, seguramente terminarás aprendiendo React, Angular o Vue.

La pregunta correcta nunca es "¿qué framework es mejor?", sino "¿qué problema necesito resolver?". Los frameworks cambian con el tiempo; los fundamentos permanecen.

4. Los errores más comunes al empezar

Hay algo que es muy probable que te pase, más tarde o más temprano: sentir que todo el mundo parece saber más que vos, que aparecen tecnologías nuevas todas las semanas y que nunca terminás de entender qué deberías aprender.

Prácticamente todas las personas que empiezan pasan por esa etapa, pero es bueno tenerlo presente para saber reconocerlo a tiempo. Porque muchos de los problemas no vienen de la dificultad de programar, sino de intentar aprender demasiadas cosas al mismo tiempo.

Estas son algunas de las confusiones más frecuentes.

"Tengo que aprender muchos lenguajes"

No. Necesitás aprender uno. Porque los conceptos importantes (variables, funciones, estructuras de control, algoritmos, modularidad, depuración, etc.) existen en prácticamente todos los lenguajes.

Además, cambiar de lenguaje suele ser mucho más sencillo que aprender el primero. Por eso, dedicar meses comparando Python, Java, C# o JavaScript normalmente es perder tiempo. Elegí uno y empezá.

Podés ignorar por ahora: compiladores, optimización, patrones de diseño, arquitecturas de microservicios y diferencias entre lenguajes. Elegí uno y empezá a programar.

"Tengo que aprender todos los frameworks"

Tampoco. Los frameworks existen para resolver problemas específicos. No son un requisito para aprender programación.

Cuando entiendas los fundamentos y empieces a construir aplicaciones reales, recién ahí tendrá sentido aprender el framework que mejor se adapte al tipo de proyecto que querés desarrollar.

No necesitás aprender React, Angular y Vue. Ni Django, Flask y FastAPI. Ni Spring Boot y Quarkus.

Normalmente alcanza con aprender uno de cada categoría cuando realmente lo necesitás.

Podés ignorar por ahora: comparativas entre React y Vue, Django vs FastAPI, cuál framework tiene más salida laboral o cuál es más rápido. Primero aprendé a resolver problemas; elegir un framework será mucho más fácil después.

"Tengo que aprender todas las tecnologías que aparecen en las ofertas laborales"

Las ofertas suelen listar una enorme cantidad de herramientas, pero eso no significa que esperen que un postulante junior domine absolutamente todas. Muchas veces representan una lista de deseos más que un conjunto de requisitos estrictos. Lo importante es desarrollar una buena base y demostrar que sabés aprender tecnologías nuevas.

Las herramientas cambian constantemente, mientras que la capacidad de aprender permanece.

Todavía no necesitás preocuparte por: Kubernetes, Docker, CI/CD, arquitecturas distribuidas, escalabilidad, sistemas de mensajería, optimización de rendimiento, machine learning o especializarte en un área. Todo eso puede venir más adelante.

"Tengo que decidir hoy a qué me voy a dedicar"

No hace falta. Pocas personas terminan trabajando exactamente en el área que imaginaban cuando comenzaron.

Algunos empiezan haciendo desarrollo web y luego pasan a datos. Otros descubren que disfrutan la ciberseguridad. Otros terminan trabajando con infraestructura o inteligencia artificial.

No conocer todavía tu especialidad no significa que te estés quedando atrás.

"Necesito saber absolutamente todo antes de buscar trabajo"

Nunca vas a sentir que sabés todo. Ni siquiera después de muchos años. Porque la informática cambia demasiado rápido.

El objetivo no es llegar al punto en que no tengas dudas, sino llegar al punto en que seas capaz de aprender las que vayan apareciendo.

5. ¿Cómo priorizar qué aprender?

La informática evoluciona constantemente: cada año aparecen nuevos frameworks, nuevas herramientas, nuevos lenguajes y nuevas modas. Intentar seguir todo al mismo tiempo es imposible.

Una buena forma de decidir qué merece tu tiempo es hacerte estas preguntas:

¿Es un fundamento o una herramienta?

Los fundamentos cambian muy poco, mientras que las herramientas cambian constantemente. Entonces, invertir tiempo en fundamentos suele dar mejores resultados a largo plazo.

Por ejemplo, son fundamentos:

  • lógica de programación
  • algoritmos
  • estructuras de datos
  • depuración
  • diseño de software
  • bases de datos
  • redes
  • sistemas operativos

En cambio, un framework específico o una herramienta concreta puede dejar de usarse dentro de algunos años. Eso no significa que no debas aprenderlos, sino que conviene hacerlo después de construir una base sólida.

¿Lo necesito ahora para un proyecto real?

Muchas personas estudian tecnologías porque alguien dijo que "hay que saberlas". Pero una mejor estrategia es aprenderlas cuando aparece una necesidad concreta.

Los proyectos reales suelen ser el mejor filtro para decidir qué aprender después.

¿Esto me acerca a mi objetivo?

No todas las personas quieren lo mismo. Alguien que quiere desarrollar videojuegos no debería priorizar exactamente lo mismo que alguien interesado en ciencia de datos.

Antes de empezar un tema nuevo, preguntate: "¿Esto me acerca al tipo de trabajo que quiero conseguir?"

Si la respuesta es no, probablemente pueda esperar.

6. ¿Qué cambia con la inteligencia artificial?

Es normal preguntarse si todavía tiene sentido aprender programación cuando existen herramientas capaces de generar código automáticamente. La respuesta corta es sí.

La inteligencia artificial cambió la forma de trabajar, pero no eliminó la necesidad de comprender lo que estamos construyendo.

Hoy un desarrollador puede utilizar IA para escribir código más rápido, generar documentación, detectar errores o explorar alternativas. Pero sigue siendo necesario entender el problema, evaluar si la solución propuesta tiene sentido y detectar cuándo la IA se equivoca o se desvía del objetivo planteado.

Cuanto mejor entiendas programación, mejor vas a poder aprovechar estas herramientas. Porque la IA puede escribir código mucho más rápido que vos, pero lo que todavía no puede hacer es decidir qué problema conviene resolver, entender el contexto completo de un proyecto o saber si una solución realmente satisface tus necesidades.

Tu objetivo no es competir con la IA escribiendo código más rápido, sino entender lo suficiente para dirigirla, evaluar sus propuestas y corregirlas cuando sea necesario.
